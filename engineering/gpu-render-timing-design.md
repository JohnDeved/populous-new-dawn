# Private opt-in GPU render timer seam

This private integration wires the reviewed helper into visible F8 profiling, frame recording and bounded exports on main edeb2c09 after PR590. No hardware validation, timing result or performance claim exists. The 2 MiB export cap is unchanged.

## Feasibility and source
Installed THREE.WebGLRenderer provides getContext(), but has no elapsed-GPU timing facility. It uses WebGL2. The optional EXT_disjoint_timer_query_webgl2 extension supports TIME_ELAPSED_EXT with later QUERY_RESULT_AVAILABLE checks, then nanosecond QUERY_RESULT reads. See the [Khronos extension specification](https://registry.khronos.org/webgl/extensions/EXT_disjoint_timer_query_webgl2/) and installed node_modules/three/src/renderers/WebGLRenderer.js. Unsupported browsers remain explicitly unsupported, not zero GPU duration.

## Lifecycle contract
Create GpuRenderTimer lazily only while visible F8 profiling is enabled. The actual call site polls once in a later RAF immediately before the render bracket, then brackets the actual live/modal render call via render(originToken, draw). No spinning, flush, finish, readPixels, or unavailable-result read is permitted. Queries contain no CPU timestamp subtraction. A pending result is never attributed to the polling callback.

The owner supplies a monotonically unique recording token and a required acceptsFrame callback that validates both recording generation and original ring slot identity. It must reject dropped warmup samples, rejected samples, overwritten slots and reset recordings. Helper checks this callback before every publication. Do not use only a wrapped array index or a reused RAF timestamp. Recorder integration tests exercise real ring wrap/reset, rejected samples, warmup and UI-throttled publication. The acceptsFrame callback checks the recorder generation and retained serial-to-slot map, not the UI-publication return value.

At most eight queries can be pending/active. Full queues and a foreign/nested TIME_ELAPSED_EXT query report busy rather than interfering. Polling completes all availability/result reads and cleanup before invoking observers; no GL query calls follow callbacks. Renders reentered from an observer still draw exactly once but are deliberately unmeasured, and recursive polling/publication is suppressed. Disjoint invalidates pending results. Context loss drops stale GL handles without deleting them; restoration reacquires the extension. Render exceptions propagate after query cleanup and do not publish partial timings. Exceptions in publication or frame-acceptance observers are contained and never skip a draw or replace its original exception. Cleanup collections are detached before publication, including context loss and disjoint invalidation. Disposal unregisters listeners, ends any owned active query and deletes owned live queries; it is idempotent. Hide/reset/disable and scene disposal must dispose this helper before renderer disposal, then create a new helper only after opt-in resumes.

Accepted results are finite, nonnegative safe-integer nanoseconds converted to milliseconds. Nonfinite, fractional, negative or inexact integer values report failed. Unsupported, busy, disjoint, context-lost and failed are distinct states and must never be encoded as numeric zero. GPU elapsed time is neither CPU submission time nor presented FPS and must never be added to nested CPU buckets.

## Private F8 integration
The actual live and modal render call sites invoke the wrapper only for visible F8. Off/hidden paths retain direct calls and allocate no wrapper/token or GPU query. Reset disposes the helper and invalidates generation; closing F8 and scene disposal dispose before renderer teardown. An overlay disposed reentrantly cannot resume queries or sampling. Nested adapter renders draw normally without replacing the outer frame token.

Recorder-issued generation/serial tokens are stored only after raw frame validation. UI publication throttling is irrelevant. Initial synchronous unsupported/busy/disjoint state is held only until that callback samples; warmup/rejected callbacks never acquire a live ring slot. Late completions update only the original still-retained slot. Serial tokens are not exported. The optional sceneRenderGpu object includes status, plus milliseconds only for available results. Old captures omit it. Parser validation rejects malformed states, preserves separate GPU evidence in worst frames, and offline cohorts summarize only available GPU milliseconds. CPU buckets and RAF cadence are unchanged. Query API overhead itself is synchronous diagnostic CPU work inside the render wrapper, not the GPU duration.

The actual download regression starts with 1,200 full-detail frames including maximum valid GPU values and adversarial UTF-8 metadata. PR590's bounded exporter retains the exact newest contiguous frames, reports omitted oldest frames, and stays within 2 MiB without mutating the ring. Real browser/GPU validation remains required. Extension acquisition exceptions are treated as unsupported on creation/restoration, keeping privacy restrictions from interrupting rendering; this is the only helper change beyond accepted e88bd895.

## Exclusive context ownership
GPU_DISJOINT_EXT is context-global read-to-clear state, not query-local state. A module-owned WeakMap permits only one GpuRenderTimer owner per WebGL2 context. A second helper remains busy without reading disjoint, querying GL, installing listeners or acquiring ownership later; recreate it after the prior owner disposes. Disposal releases ownership. Restoration retains the same owner and reacquires extension availability, which may change.

This cannot discover unrelated external code that consumes the same disjoint flag or has ended but unresolved timer queries. Integration therefore requires exclusive ownership of timer-query diagnostics for the context across all consumers. The CURRENT_QUERY check additionally avoids disrupting foreign active elapsed queries, but is not evidence that two independent timer consumers are safe. Do not enable this helper alongside an uncoordinated external GPU profiler. Installed WebGLRenderer has no competing elapsed-timer consumer.

The rejected private 20d4323c implementation and failure-first receipts remain preserved. Its callback-reentrancy and disjoint-ownership gaps are not accepted as a valid integration.
