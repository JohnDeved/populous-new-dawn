# Generated-only CMS interoperability probe

The existing **quality** job encrypts exactly 4 KiB of deterministic nonsensitive
bytes using the system `/usr/bin/openssl`, its default crypto configuration and
the pinned public OpenSSL upstream test certificate. No private key, real capture,
external plaintext path, installation, provider override or new permission is used.
The associated key is publicly known: **this recipient must never protect real data**.
This is not a production key-custody solution.

The parent Python may retain only its own canonical runtime `lib` directory in
`LD_LIBRARY_PATH`, as used by setup-python. That value is never forwarded to the
OpenSSL child: its environment is exactly fixed PATH/LANG. Arbitrary/appended
parent loader paths, LD_PRELOAD and OpenSSL configuration overrides are rejected.
On failure, only a fixed allowlisted stage token is printed publicly; raw exception
text, environment values, paths, child logs and payload bytes remain private.

The separate `cms-interop-<run>-<attempt>-quality` artifact contains exactly
`envelope.cms` and `summary.json`. It is published only after encryption settles
successfully, strict DER checks confirm AuthEnvelopedData/AES-256-GCM with a
12-byte nonce and 16-byte tag, RSA-OAEP SHA-256/MGF1-SHA-256 and the exact recipient,
and the existing tracked-input/quality gate succeeds. The fixture keeps plaintext,
raw stdout/stderr, partial output and phase receipts in a private sibling under
`RUNNER_TEMP`; none are uploaded. Failed pending directories are never published.
The five existing `full-check-*` artifacts remain receipt-only; aggregate behavior
and `QUALITY_STAGES` are unchanged. A failed probe fails quality, not a soft success.

`summary.json` binds repository, workflow/source/merge/head/base/tree identities,
run and attempt, reviewed source hashes, public-recipient fingerprints, ciphertext
size/hash/profile and the actual observed OpenSSL version/executable hash. The
version is measured, never inferred from image documentation. The binary hash is
not a complete loaded-library/configuration provenance record. Non-3.x version output
or unexpected profile encodings fail closed. Only standard absent or empty-NULL
SHA-256 AlgorithmIdentifier parameters are equivalent (RFC 4055 section 2.1).

Limits: 30 seconds aggregate workload plus bounded child/pipe cleanup, sampled
parent-plus-direct-child RSS stop at 512 MiB, 1 MiB maximum file size and 64 KiB
aggregate raw logs. An outer 35-second timeout (3-second kill grace) is a backstop.
Preflight requires 2 GiB disk, 4096 free inodes and 3 GiB host available memory.
Python-only small metadata/profile steps check the shared deadline but are not
continuously RSS-sampled; this is not hostile-process containment or a peak-RSS
guarantee. There are no automatic retries or cleanup of failed evidence.

Top-level Node tests run the Python unit tests with mocked producers. Those tests
exercise identity/configuration/terminal/profile/publication failure gates; they
are **not** crypto or hosted interoperability evidence. The quality probe performs
real encryption but makes no authentication/roundtrip claim. A separate local
consumer must independently verify GitHub run, commit, attempt, artifact identity
and ZIP digest/membership before checking this exact summary, profile and cipher
digest, decrypting with the existing public test-key fixture, and comparing the
fixed generated bytes **only after clean authenticated terminal success**.

Qualification is the actual observed hosted OpenSSL version to the pinned local
version, not an assumed 3.0.13 pair. The raw-pattern probe is separate from prior
local two-member USTAR/provenance tests and does not qualify hosted archive capture,
real recipient custody, real heaps, memory-pressure failures or general tar safety.
