# Native campaign integration

Checkpoint A is an intermediate integration, not full restoration of campaign or
result UI. It composes the reviewed native model/result contract/all-world renderer.
The legacy completion ledger and profile envelope remain version 1; the additive
native extension carries 25 byte flags and explicit history provenance. Checkpoint
version 3 and database version 1 are unchanged.

Completion-only migration is a preservation policy, not recovered play history.
Recorded supported completions remain replayable, then one non-victory transition
opens the first incomplete mission. Sorted wins are never replayed. Old-tab ledger
additions join completion bits, preserve available bits and downgrade provenance.
Malformed records/extensions are salvage-only and never overwritten. Restore does
not persist migration. Eligible completion and selector events read/merge/recompute
and put in one transaction; failed events remain local for a later authorized retry.

The native selector receives mask-5 selectability, separate inspected selection and
recommendation anchor. All 25 source records remain visible; only missions 1–23
can launch. Tutorial 79 uses its separate entry. F8 at startup/selection opens a
diagnostic picker. F8 gameplay performance and F9 spell testing remain separate.
Debug launches cannot save or award completion, including after Restart. Existing
clean checkpoints may continue even when newly migrated campaign flags lock that
world. Public campaign start independently checks both membership and availability.

The shared public diagnostic browser helper now uses F8. Existing save/progression
fixtures must be migrated explicitly to native profile/checkpoint fixtures; calling
the helper does not establish earned progression. Result-stage and remaining browser
adapter migration are checkpoint B. Full check/build and rendered acceptance remain
required after the complete candidate is independently reviewed. No parity claim,
source-pin activation, production profile mutation or mission24/25 support is made.

Checkpoint B runtime replaces automatic result statistics and current+1 continuation
with a world-owned terminal overlay, fresh-Space statistics, pending exit and native
selector. Statistics owns pause and actual HUD removal/viewport expansion. Selector
Back retains the terminal world/statistics. Popup, file/modal, flyby and input-mask
owners remain earlier. Browser focus pause is released on its own fresh press,
without simultaneously advancing result stage. Enter/click do not navigate results.

Static native follow-up establishes the separate counters: paused-gated logical
turns own the >10 admission threshold; admitted input cycles own prompt/status blink.
The input-cycle adapter uses elapsed83ms intervals (floor1000/12), independent of
pause, game speed and refresh rate. Its zero-at-scene-entry epoch and elapsed catch-up
are explicit browser adaptations, not exact original scheduler/save emulation.
Western result text uses raw verified F3/F4 pixels without guessed CSS color tint.
Low-resolution panel composition reuses the same verified native tile owner as
campaign popups; very small viewports uniformly fit rather than clipping as native
320x200 does. All ten unavailable counters remain explicitly unavailable.

The runtime checkpoint is still not acceptance-complete: existing browser and unit
consumer adaptation, independent review, source-bound quality checks, rendered win/
loss/fork/profile roundtrips and serialized standard full gates remain outstanding.

The held-drag source-admission profile adds only the reviewed result-clock frame
route. It retains all six historical profiles and binds the clock functions, import
and per-scene initialization in addition to the existing 17 owners. Reconstructing
the exact old frame still admits the historical route; unused new declarations do
not affect it. Partial frame edits, changed clock owners or mixed recording routes
remain rejected. This is a bounded source contract, not rendered/performance or
native scheduler acceptance. The snapshot setup regression executes the actual Home
Load handlers and proves both forced-resume interception and failed-load refusal.
