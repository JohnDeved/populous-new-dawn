# Runtime-owned ordinary terrain picking

Private candidate, not a measured performance improvement.

Only the real GameScene constructor opts into this internal path, after its first terrain rebuild. Generic RenderView.pick/pickCandidates/screen and native occlusion remain unchanged. The view and terrain must retain ordinary plain fields, methods and storage while owned: releaseRuntimeTerrainPicking(view) BEFORE adding custom accessors, proxies, methods or traversal callbacks. Arbitrary monkey-patching is not detected by identity checks. Generic/custom picking stays supported through the original path.

Current XYZ is read every query, including unversioned setY, nonfinite inputs and disagreeing duplicate corners. No height or cross-query projection cache exists. The producer's geometry replacement explicitly rebinds; submitted index is obtained after the original visibility preparation. Camera/view/water updates stay in their existing phases. Scene view/terrain replacement falls back using the current objects. Dispose/custom release permanently revokes the capability, detaches retained storage and never mutates an active query's lease. Later generic queries do not regrant ownership. Nested queries use the generic path.

The owned loop uses six Float64 lanes (world XYZ, projected NDC XYZ) and two private working records, calling the unchanged projectPoint arithmetic. Full matrix reciprocal/multiply order, relative height conversion, fixed-point wrap, float32 projection outputs, NDC divisions and accepted-hit addScaledVector order remain exact. Returned candidate points are independently owned. Native retained caches never share these arrays.

Numeric storage grows lazily from 256 slots up to the fixed 98,304 raw-grid-vertex cap: at most 4,718,592 retained bytes, plus existing corner/slot maps and two records. Growth temporarily retains the old array while copying, so this is not a peak-memory or GC bound. Public generic queries may also allocate their existing transient working representation. No per-vertex busy/finally or descriptor scan is added. Source-level avoidance of four intermediate object requests per projected unique corner is not proof that V8 materialized them, nor evidence of a runtime win. Whole-query measurement and independent implementation review remain required.

Tests use the actual authored Level2 terrain, current water/raw mutations and previous-rendered Painter state through the shipped scene input function, plus direct numeric oracle, ordered candidates/winners, native isolation, retained results, lifecycle/recovery, generic access order and bounded-capacity cases. An optional PND_TERRAIN_BASELINE points at an untouched render-view.ts source to compare against the original implementation rather than the generic path in the edited module.

The constructor regression instantiates real GameScene classes with only DOM/canvas, renderer and texture/file IO leaves supplied. It compares untouched baseline initialization, null-index first query, real render callbacks, previous-rendered changed-view picking and disposal. Generic regression probes preserve the exact receiver lookup trace and metrics-getter argument order, including a getter that replaces scene.view before invocation; unowned disposal adds no new receiver dispatch.
