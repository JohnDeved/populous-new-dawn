## Exact setup writes

Start M1 through the existing harness's public mission chooser, in a fresh owned
profile at 1440 × 1000, DPR 1. Require the current scene/store pair, no existing
gifts, no acquisition controller/requests, no pause, and a hidden overlay.

1. Call `createGift(world, 'lightning', authoredLightningHead, 0,
   authoredLightningHead.ordinarySpellReward)` once. Keep all ordinary authored
   provenance, the generated ID/serial, completed turn and local recipient.
   Override only this gift's `phase: 6 → 1` and `remaining: 82 → 77`.
2. Let the real RAF/world turn generate and drain its request, and the real
   acquisition visits produce its first active 100-visit pulse. In the
   synchronous observer after that original visit returns, call `createGift`
   once for the authored Bridge head, then once for the authored Lightning head,
   with the same explicit arguments and the same two field overrides each.
   The next actual object turn produces phase 0/timer 76 and queues those gifts;
   the original scene drain must select Lightning then Bridge and leave Bridge
   as the winner without advancing either controller or consuming either RNG.

Each createGift call increments only `world.nextId`, appends the same new object
to `world.effects` and `world.gifts`, and initializes that new object's fields.
Each synchronous transaction retains full created gift/provenance/override data,
array lengths and IDs, plus before/after acquisition, gift, stock and both RNG
snapshots. It compares the serialized World outside nextId/effects/gifts before
and after, verifies unchanged existing array prefixes, and verifies gift/effect
object aliasing. The serializable audit is bounded to 64 MB per transaction.
There are exactly three created gifts and six explicit field assignments.
No source head, stock, request queue, controller, clock, speed, RNG, or renderer
state is directly written by setup. No manual tick, clock visit, handoff, draw,
RAF cancellation, canvas hiding, or injected geometry occurs.

Fixture setup writes are distinct from the subsequent original callback and
Canvas observations. Wrappers call each original exactly once with its original
receiver and arguments; errors are recorded rather than thrown into the live
clock. Owned wrappers are restored, or the row fails. The profile is a disposable
isolated fixture run: it does not create or overwrite a user checkpoint.
