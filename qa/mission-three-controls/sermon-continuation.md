## Preserve the committed checkpoint

Every observed UI Save in an owned profile records the maintained observer's full
committed checkpoint digest. Ordinary preparation Load also retains its existing
verified readback. A failure or resource stop preserves that known latest save
and reads its digest again instead of writing the failed exploratory world over
it. This keeps harness-owned terminal readback, browser/server cleanup and lease
release on the normal return path.

The explicit command`stop-preserve-latest` pauses normally, verifies the actual
latest digest, records an incomplete stop, and closes through that same path. It
does not issue Save or use process signals. It also takes precedence over a new
automatic sermon capture, so a requested preservation stop cannot itself replace
the checkpoint. A mismatch remains visible; no metadata or storage repair occurs.
It is the sole command in its batch and dispatches before ordinary diagnostic,
health or budget processing. Missing expected state, mismatched storage and
readback exceptions are terminal failures too; they never invoke fallback Save.

If intended-save verification fails, the driver annotates and moves its emitted
sermon record to`sermon-record-withheld.json`. The valid forwarding filename is
absent and the validator rejects the blocked annotation even if renamed manually.
The first failure reason is retained. Generic harness`continuationVerified`
still concerns its own terminal readback/source/lease checks; it does not establish
that the scenario's intended Save was preserved. The harness remains unchanged.

## Genuine saved-sermon Load

After a real sermon Save,`sermon-record.json` binds the actual committed full,
actor, terrain and stock digests; original source/profile/run; declared pool;
first-owned witness; exact listener/Preacher and retained Blue identities;
acquisition milestones/inputs; active time and every inherited failure.

`M3_SERMON_RECORD` selects that task-owned record instead of
`M3_PREPARATION_RECORD`. Before ordinary Load, exact profile/origin and committed
checkpoint identity must match. The source must match, or use one explicit
independently reviewed correspondence already admitted by the maintained harness.
The original saved source is retained; no further saved-sermon source transition
is supported. Each same-source retry uses its immediate predecessor's forwarded
record. Application/runtime/root/origin checks remain the harness's responsibility.

Load auto-resumes. A fresh observation epoch must still see the exact living
Yellow listener owned by the saved Preacher and all retained Blue identities.
The driver immediately pauses, preserves the inherited declaration without
rearming, and allows the ordinary cancellation order. It inherits old failures
explicitly, so they cannot become a clean journey. It does not award the planned
post-cancellation reload milestone merely for entering this segment. The normal
cancel→reload→exact singleton conversion sequence remains required.

The record contains provenance, never a World to inject. Run14 did not emit this
new schema. Its observed Save may only receive a provenance record after an
