## Why this product subset is not justified yet

The established Mission6 case in `tests/mission6.test.mjs` explicitly observes three Warriors plus one Preacher. A whole-Warrior gate excludes that mixed cohort and does not address the captured issue248 discriminator.

The existing natural Mission2 raid test supplies ordinary player actions and an authored Warrior quota, but explicitly permits both Warrior and Brave fallback. It observes selected task members, not the complete same-tribe registered state14 set including unlisted people. An authored quota or those source assertions therefore cannot establish an all-Warrior full-set admission witness. The author likewise reports no accepted such witness. No new gameplay run is warranted merely to manufacture a justification for the temporary gate.

Universal activation is also not currently safe to assume. The previously accepted `004ce2c0` maintenance bytes contain explicit `004f2440(person,0)` calls at model5 `004ce7f3`, model7 `004ceab8`, and special-bit branch `004cebc9`. Giving new positive ownership to those people while omitting their release can prolong the shared-selector reservation beyond its native release point. This is a new retention risk, distinct from an excluded port cancellation losing ownership back to the previous zero-field behavior.

The whole-Warrior gate is a coherent way to avoid that specific activation risk, but coherence alone does not make it the appropriate product repair. With no established useful current case, the selected next step is the finite original model5/model7 release contract, not implementing the subset to turn supplied tests green.

## Useful review findings retained

1. **Write-side identity is essential.** Fixing only selection busy while leaving the presentation source as write authority lets actual defense/type24/type20 selection actions overwrite the registry with a stale alias. The revised proposal explicitly captures registered identity for selected-flag clearing, state initialization and assignment/adoption. Clearing the authoritative flags3 bit0 is supported; copying a stale entire flags word is not. Any later implementation must independently verify release/adoption handoffs rather than treating this prose as proof of every cleanup path.
2. **Same-owner writes still reconcile arrays.** Actual assignment writes that reassert the same byte must remove incompatible raid arrays. Numerical equality is not evidence that an old array is consistent. Type24 writes99 directly and must not accidentally gain the raid helper's different7f semantics.
3. **Retirement must be nonpartial.** Prevalidation must prevent task freeing if matching ownership cannot be safely cleared. Skipping an invalid flags3 owner and freeing/reusing its slot would orphan the reservation. Admission must not create ownership that the supported release cannot clear. Absent7f alone does not imply invalid assignment or justify fabricating a zero byte.
4. **Early retirement is an explicit port policy.** Matching cleanup at the port's phase6-empty and failed-staging free exits is a coherent consistency requirement for any newly introduced reservation. It must remain distinguished from proof that those port exits are native phase23 branches.
5. **Old-save emission protection is narrow and justified.** A read-only guard can stop raid orders from being issued to a known authoritative foreign owner without rewriting historical arrays or the established phase6 snapshot behavior. It does not reconcile old damage-credit, readiness or settlement consumers, and must not be described as native old-save membership proof.
6. **No hidden model carry was found in the named transitions.** The reviewed training path allocates replacements through `addUnit` and `createLivePerson`; conversion transfers order tails, not computer assignment. Preacher conversion and hypnosis also create new people with assignment0. The inspected dead-hypnosis path changes tribe, not model. Current nativeFlags7f writers clear bit0 or OR bit1 for wild people; no current producer shown sets bit0 on a newly admitted Warrior. These are finite current-source observations, not proof of a full original allocator/save lifecycle or a gameplay witness.
7. **Cancellation retention stays exact.** The accepted ordinary single-command19 Warrior closure requires retention, but shared references, associated-object destruction, alternate cleanup conditions and other discard paths remain outside that proof. Broadening the product claim beyond this predicate would need its own source/consumer evidence.

The revised proposal incorporates these points and preserves the known limitations. Its all-model3 collection gate acts on the entire registered state14 set, including unlisted people, before any write or roster replacement; it never silently admits a subset. No implementation of that policy is accepted now.
