## Browser asset

The generated output is deliberately limited to:

- `public/favicon.ico`
- SHA-256: `54a52520ffe984bc877c395051ee103584d93a048a9933e10cfac8c012f3b287`

The ICO contains all three embedded sizes and copies each `RT_ICON` payload without image decoding or resampling. That retains the original palette/XOR pixel bytes and AND transparency masks exactly. The existing metadata entry in `app/layout.tsx` points to `/favicon.ico`. The previous `public/favicon.png` file is left unchanged and is no longer the active metadata icon.

## Reproduce and verify

From the repository root:

```sh
python3 scripts/extract-exe-icon.py /path/to/hash-verified/d3dpoptb.exe --output public/favicon.ico
python3 scripts/check-original-favicon.py /path/to/hash-verified/d3dpoptb.exe
```

The extraction helper reuses the repository's existing SHA-locked PE32 reader, walks only PE resource ids 14/125/1033 and the referenced icon ids 2, 3 and 4, validates the reviewed hashes above, and writes a deterministic ICO. The static checker independently rechecks the source executable/group/resource bytes at their reviewed file offsets, verifies decoded RGBA/transparency fingerprints, reruns the extractor to a temporary file, and requires the regenerated bytes to match the tracked ICO exactly.

The focused browser acceptance additionally requires emitted icon metadata to reference `/favicon.ico` and the served response bytes to match the tracked multi-image ICO exactly.

No claim is made about Windows shell scaling behavior beyond the three embedded icon resources themselves, and no favicon artwork variant is inferred or synthesized.
