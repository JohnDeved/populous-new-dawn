# Ordinary native G input

Issue [#219](https://github.com/JohnDeved/populous-new-dawn/issues/219), based on
`3b899125cc8cedef938823718ad5d44f49957b66`. This is a bounded ordinary on-foot
input repair. Busy-controller handoffs, fully settled native Guard movement,
historical uninterrupted phase and whole-family animation parity remain open.

two keyboard-setting cases. G action0xc1 emits tribe command0x82; the shipped
default keeps selection. The port exposes no alternate retain-selection setting.

`00443b40` allocates one shared command30 aimed at the current exact Shaman
identity, then sets flags2 bit16, clears old queues and attaches the shared slot.
Repeated G replaces the order; it does not toggle off. With no selected non-Shaman,
including Shaman-only selection, only state10/status30 people are anchored and
cleared. Unadopted state19 command30 survives. An absent Shaman pointer prevents
either operation. Configuration saves target identity; a replacement Shaman does
not retarget the old order.

Allocation failure is not atomic refusal. Native still clears and attaches0,
including record0 references/active accounting. Cleanup can free a slot for the
next allocation retry; the supplied three-person exhausted case ends `[0,1,1]`.
The port deliberately preserves these proved queue effects. This does not turn
slot0 into a usable order or claim useful Guard behavior under exhausted capacity.

`004d42a0` preparation and real state10 initializers own adoption and setters.
The same person enters walk source40/draw18; f1 resets, valid f2 survives and an
out-of-range f2 clamps. G itself and deselection do not reset counters. Near-target
`0043daa0` clears pursuit without a setter, so it does not establish a physically
stopped follower. The target predicate rejects native vehicle occupancy even when
the port's `Unit.inside` remains null. Distance tests sign-extend each coordinate
before subtraction: both axes `<824` are near; either goal displacement `>=440`
replans. These changes do not alter general wrapped movement physics.

Building containment is different: a living Shaman who enters a Tower remains a
valid Guard target. The same consumer resolves the occupied building's outside
point. A public Shaman-to-Tower command regression covers real admission,
continued command30, fresh-G outside destination and cancellation anchor; no
inside flag is used as a target-loss substitute.

Cancellation/completion use `00433490`/`004389c0` command-position semantics before
clearing. For command30 this reads the saved target's coordinates even when its
class/death/vehicle state makes the guard consumer finish. The live port shares
that raw lookup, using the follower position only when the target record is absent
from its retained world. Complete removed-object-pool history remains unported.

## Live integration boundary

Public `guardShaman` selects one mode for the entire selected non-Shaman batch.
Native input accepts Blue living class1/model2–6 owners in ordinary native state17,
19, or supported state10 move3/Guard30 queues. It rejects competing flight, fight,
casting, lift, building-entry, builder, inside, work, target, tree, harvest, delivery,
vault, attack-reservation, native work-group, vehicle, protected/dead/airborne/ghost,
different-route or legacy-path ownership. A genuine pending G can retain state10
with an empty queue after cancellation or exhaustion. All unsupported and mixed
batches execute the former legacy operation unchanged; they are not native parity.
No-selected/Shaman-only cancellation applies to supported adopted native guards.
Old boolean guard history stays untouched by that cancellation.

The port uses existing `World.units` roster order, not `World.selected` order.
It has no native tribe linked-list equivalent. Tests reverse selection order to
verify this boundary. Shared/exhaustion semantics match a supplied roster order;
which ordinary follower receives a failed slot cannot be claimed identical to
the original linked-list traversal.

Optional `LivePerson.guardInputPending` marks only real G mutation on the same
native record. It preserves renderer ownership through state10/status0 pending
replacement and cancellation. The ordinary turn routes that marker through the
existing movement/preparation/queue controller, including empty-queue completion,
before normal resting. It is removed only after actual adoption/completion, or
explicit superseding order cleanup. Protected preparation, protected cancellation
and passenger early returns retain it. No status spoof, eager initialization,
frame0 policy, or generic state10/status0 renderer ownership is introduced.
Native Brave guards also bypass the legacy idle auto-housing assignment.

A new move/attack/worship/entry order can supersede G before its first turn.
Replacement cleanup clears that pending queue before the legacy resting adapter
runs its eager initializer, so it never initializes the discarded Guard. The
original caller `00444f60` clears/attaches first, then initializes the replacement;
its deferred bit16 survives. A native caller composition confirms that the next
`004d42a0` can legitimately initialize the replacement again. The port therefore
preserves bit16 rather than forcing equality with a no-G next-turn control.
Immediate source/phase/target/speed/RNG comparisons and next-visit queue checks
separate this genuine deferred behavior from premature old-Guard startup.
The independently executed supplemental probe is SHA256
`4d41f43b90d27354fa5c01dfc601d064f800e7b9b99f6c5694feb18a0d1605d5`,
result `f27f202d9f936df58d1c1b1359a807649cfdee75ae79c89a99447bf2c5dc3a8a`.
It adds only acknowledgement leaf00436330 to the frozen baseline's supplied
destination/UI leaves; physics, OS input and complete world scheduling remain
outside that native caller-composition proof.

Current checkpoints preserve the optional marker, person aliases, pool and phase
through their existing structured-clone storage. No migration reconstructs a
native target/order/phase from old `Unit.guard`. An old unsupported state10/empty
queue remains on its prior toggle; a later supported ordinary owner can accept
fresh G. Paused input, replacement, cancellation and resumed clone/migration are
tested separately from the ordinary browser Save/Load gate.

## Acceptance status

Focused native-vector and live tests cover shared/partial replacement, empty and
Shaman-only cancellation, exhaustion, signed boundaries, same-person phase,
protected/early returns, raw target anchors, checkpoint/pause, 30/60/120/144 Hz and
irregular schedules, and whole-world equivalence to the old busy/mixed operation.
These tests use supporting mechanics fixtures; they do not substitute for normal
Mission10 Firewarrior training through hut149 with its ordinary mana, public G,
deselection, repeat/cancel, following and Save/Load observation.

Scoped formatting and typecheck pass. Scoped ESLint findings are byte-identical
to baseline; normalized Oxlint reports 388 baseline and 388 candidate findings,
with none introduced. Global format still flags the unchanged baseline
`render-view.ts` and `viewport-bounds.ts`. The retained receipts distinguish these
baseline findings from this change instead of weakening the checks.

Standard full check/build, fresh full-diff review and that real-clock rendered
gate remain required before completion. No parity
ledger or deployment changes are included. Issues #4, #60 and #214 remain open.
