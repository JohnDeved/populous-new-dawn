# Initial Angel attachment: real mesh instead of Warrior artwork

Scope: the initial-model checkpoint in PR #823, not complete Angel parity.
The subsequent bounded strike extension is documented in [strike.md](strike.md);
statements below describe the initial checkpoint rather than that extension.

## Original source identity

The original `d3dpoptb.exe` SHA256 is
`3a5065c7420b3fcde208bf220bc86dfbac95e025ab2492caf9c7ea5308dfbe4f`.
It and selected object files were extracted as data from the documented archive
SHA256 `6aa6c366809ea1d9575ec1d31a24527a95c7332f0a1d2ab692f7a602e7e10702`.
No original executable or installer was launched. The importer pins all eight
original bank inputs; independent bank 2/bank 6 decoding must produce equal geometry.

Retained source and fresh static disassembly establish:

- `../mission5-angel.md` and `../../generated/004db980.c`: the model 8 combat
  payload owns a separate class 6/model 8 visual attachment. Its initial call is
  `004de440(attachment, 0x45, 1)`, not a person-sprite source.
- `../../generated/004fa530.c`, model 8 branch: allocation selects processing
  state 9, not state 8. The class 6 dispatcher has no state 9 controller body.
  Do not confuse the model 8 value with dispatch state 8 / `004fc570`.
- `004de440.asm`, `004de50e..004de568`: initial mode calls the object setter
  with descriptor 4 and model 69, copies OBJS byte 7 to the morph index, and adds
  render bits 0x8080. This is static analysis, not a fresh CPU execution oracle.
- Original model 69 has 111 faces,87 points and scale 160. Morph record 5 at
  `5 * 0x170` lists 70, 71, 72, 73, 74, 75 with six duration fields of 1. The established
  `process_morph0`/`0040cc60` contract makes each segment 2 frames, 12 total.
  Preserve model 69 topology/materials and interpolate corresponding raw keypoints;
  the keys each have 157 faces and must not replace the base topology.
- Descriptor 4 has mode 4 and step 4. Existing `stepObjectAnimation` advances this
  loop on eligible presentation visits. The current 24 Hz application adapter is
  retained, not claimed as an unconditional original wall-clock rate.

The `004de440.asm` ranges were decoded with installed GNU objdump in Intel syntax:
`--start-address=0x4de440 --stop-address=0x4de510` and
`--start-address=0x4de50e --stop-address=0x4de580`. Overlapping range boundaries are
intentional; only the complete function through return 004de568 is evidence.

## Live change and explicit remaining gap

Previously `scene-effects.ts` built a draw 15 Blue Warrior `stagger` sprite for
all Angel effects. The actual `makeFx`/`animateFx` path now uses model 69 and its
original loop with existing textured model projection, native heading and the
existing shrink timer. The shared presentation visitor owns a serialized
counter/display latch; the renderer does not advance state. Pause, land pause
and current checkpoint continuation retain the latch.

**Model 69 remains the initial-model presentation adapter throughout the current
simplified browser Angel lifecycle. It is not the correct native model for every
later movement state.** In particular `004ddb30` selects 62 for native movement
mode 3, or controller state 6/substate 2, except controller states 7/8. Native ordinary
chase enters mode 2 and then mode 3 after 2 visits (`004db980` raw controller state 6/substate 1).
The browser's broad `seeking` and `striking` phases do not own those fields; this
patch does not invent a 62/69 mapping from them. Native transition keys 76–78,
attack-specific pose overrides, tilt/roll and exact chase/landing physics remain
unimplemented. The existing movement, target choice, timers, damage, RNG and
outcomes are unchanged. No full-controller, all-state sprite or release credit.

The smallest next presentation step needs an actual native mode 2→3 visit owner
and transition byte+0x7c, not a guessed replacement at `seeking` entry.
`004de440` transitions through 76–78 before switching the base mesh; direct 62/69
replacement would omit this native transition.
