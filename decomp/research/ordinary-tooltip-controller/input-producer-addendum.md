## Result and physical-device qualification

The game's mouse producer reads the actual configured second button at byte offset 13, emits `0xF1`, and preserves press/release state to native cases `0x72`/`0x73`. This is not inferred from the current port or from a default structure alone. The actual format uses `DIDFT_ANYINSTANCE`; Microsoft describes the second button as **generally** right on a traditional mouse. Thus the supported claim is the normal second-button/right-button route, not an invariant physical switch across every device, remapping or failed device configuration. No native runtime/device was exercised.

## Finite acceptance boundary and next source target

The formerly missing F1 producer is closed for the documented normal system-mouse format, with the hardware/configuration qualification above. The configuration bit's direct lifecycle and selection-count relation are also concrete. **Complete physical inspection/context equivalence remains held.** Port right-click reachability is proven separately; this pass does not authorize an implementation or erase the tooltip cache side effects established by the prior packet.

One useful next bounded comparison is `0045db60`'s window2/mode0x11 entry/exit: its immediate `0045ed10` UI owner, existing cases b9/ba, and the corresponding current browser modal/pause/overview state. That target can settle whether the configuration guard is already represented or missing, without a general input rewrite. The global `land_flags_1 &2`, `level_flags_1` gates, valid-cell producer and any mode writers outside `0047a550` remain explicit; they should not be asserted equivalent without their own named producer evidence. No new pass on those owners was performed here.
